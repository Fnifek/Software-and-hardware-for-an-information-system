# Подсистема приёма и предварительной обработки данных (ЛР2)

Документ описывает решения, реализованные в коде, и связь с архитектурой ЛР1.

## 1. Тракт обработки

```
ISensorSource → RingBuffer → Sampler → MovingAverage(4) → EmaFilter(7) → Sink
```

| Блок | Класс | Ответственность |
|---|---|---|
| Приём | `ISensorSource`, `ModelSensor` | опрос датчика, приведение к °C, метка времени, номер отсчёта |
| Буфер | `RingBuffer<RawSample, 4096>` | сглаживание скорости потоков, диагностика переполнений |
| Дискретизация | `Sampler` | равномерная сетка 100 Гц, компенсация ухода часов |
| Фильтрация | `MovingAverage(4)`, `EmaFilter(7)` | подавление ВЧ-шума и сетевой наводки |
| Потребитель | `Sink` | запись в БД, график Qt, экспорт CSV |

## 2. Почему буфер кольцевой и без блокировок

Источник работает на 200 Гц, потребитель — на 100 Гц. Мгновенная скорость
потребителя ниже, но обработка пакетная, поэтому очередь нужна как
демпфер при кратковременных провалах планировщика. Ёмкость 4096 отсчётов
(≈20 с при 200 Гц) с запасом покрывает паузу сборщика мусора/GUI.
SPSC-схема с atomic-индексами убирает mutex из горячего пути; при
переполнении новый отсчёт отбрасывается и инкрементируется счётчик
`overruns`, что важнее блокировки потока приёма.

## 3. Дискретизация

`Sampler` хранит абсолютный `next_` и прибавляет период, а не sleeps
«на период» от текущего момента. Это исключает накопление ошибки.
Если поток проснулся позже, чем на половину периода, такт считается
пропущенным, `missed` увеличивается, а сетка восстанавливается от
текущего времени.

В Windows стандартный квант планировщика (15,6 мс) больше периода 10 мс,
поэтому конструктор `Sampler` вызывает `timeBeginPeriod(1)`, а деструктор —
`timeEndPeriod(1)`. Без этого на стенде обрабатывалось 23 такта за 3 с
вместо 300; после повышения разрешения — 300 тактов при 600 принятых
отсчётах и нуле пропусков.

## 4. Фильтрация

КИХ-усреднение:

```
Y[n] = (1/N) * Σ X[n-j],  j = 0..N-1
```

EMA:

```
EMA[n] = P[n]*α + EMA[n-1]*(1-α),  α = 2/(N+1)
```

Выбор N: перебор по сетке на модельном сигнале (60 с, 100 Гц) дал
минимум СКО при N_КИХ = 4 и N_EMA = 7. Окно 4 даёт нуль АЧХ на 50 Гц,
что существенно для сетевой наводки; EMA сглаживает остаточный шум.

| Вариант | СКО, °C |
|---|---|
| без фильтрации | 0,606 |
| КИХ, N=4 | 0,178 |
| EMA, N=7 | 0,158 |
| КИХ(4) + EMA(7) | 0,136 |

Групповая задержка тракта — около 4 отсчётов (40 мс), что учитывается
при привязке метки времени к физическому процессу.

## 5. Ограничения и развитие

- Модель не учитывает теплоёмкость радиатора и гистерезис кулера.
- При пропуске такта используется последний доступный отсчёт; для
  критичных измерений нужна интерполяция по меткам времени.
- Аппаратный источник (`HardwareSensor`) — точка расширения: COM-порт,
  АЦП или драйвер; интерфейс не меняется.
